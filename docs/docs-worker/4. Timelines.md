# 4. Kế hoạch Worker — 3 tuần

Kế hoạch chi tiết của Vũ cho dịch vụ worker, bám vào bảng epic tổng (`docs/introduction/1. Timelines.md`): **A4 (Worker pipeline, Sprint 1-2)** và **A5 (Độ tin cậy job, Sprint 2)** là việc chính; tuần 3 dành cho hoàn thiện, phối hợp **C5** (quan sát/co giãn) và chuẩn bị **A8** (benchmark).

Tổng effort phân cho worker: **A4 (4,0) + A5 (1,5) + phần phối hợp** ≈ **7,5 pd** trong 3 tuần (~2,5 pd/tuần). Frontend (A6) chạy song song nhưng không thuộc tài liệu này.

## Tổng quan 3 tuần

| Tuần | Chủ đề | Kết quả cuối tuần |
|---|---|---|
| **1** | Contract + POC FFmpeg + khung worker | **M1**: POC transcode chạy; worker skeleton nhận message từ LocalStack |
| **2** | Pipeline hoàn chỉnh + độ tin cậy | **M2**: e2e local `COMPLETED` với đủ assets; heartbeat, SIGTERM, DLQ pass (`make chaos`) |
| **3** | Cứng hóa + lên cloud + chuẩn bị benchmark | Worker chạy trên AWS qua ASG; metric/log đủ cho dashboard C5; kịch bản benchmark sẵn sàng |

## Tuần 1 — Sprint 1: Nền móng

### Mục tiêu
Contract chốt xong để cả nhóm chạy song song; chứng minh được FFmpeg làm được việc cần làm.

### Việc cụ thể

| # | Việc | Ước tính | Ghi chú |
|---|---|---|---|
| 1.1 | Cùng Phương chốt 5 file `contracts/` liên quan worker: `video-state-machine.md`, `sqs-job-message.schema.json`, `s3-key-convention.md`, `dynamodb-tables.md`, `upload-limits.md` | 0,5 pd | Ngày 1-2; cả 4 người review |
| 1.2 | **POC FFmpeg** trên file local: chạy tay lệnh ở [[3. Architecture]] mục 3.5 với video mẫu, kiểm tra `master.m3u8` + 2 rendition + thumbnail phát được bằng hls.js/VLC | 0,75 pd | Đây là việc rủi ro cao nhất — làm sớm nhất, sai thì biết ngay |
| 1.3 | ffprobe POC: lấy duration/height/codec; thử 4-5 video "bất thường" (đuôi giả, 1440p, dài 6 phút, không audio) | 0,5 pd | Nhập cho bảng errorCode |
| 1.4 | Khung `worker/` (Go): `cmd/worker`, `config`, `logging`, chạy được bằng `go run` trỏ `AWS_ENDPOINT_URL` vào LocalStack | 0,5 pd | Cần M0 (ngày 3): `make infra` chạy xong |
| 1.5 | `storage` + `state`: tải/đẩy S3 và `UpdateItem` DynamoDB có điều kiện (thử trên LocalStack bằng script tay) | 0,5 pd | |
| 1.6 | Ghi rõ lệnh chạy, cổng (không mở cổng), biến môi trường cho Lưu viết Dockerfile | 0,25 pd | Chặn C0 — không được trễ |

### Điểm phụ thuộc

- **M0 (ngày 3)**: `make infra` chạy — nếu LocalStack chưa xong thì 1.5-1.5 tạm dùng interface + mock, tuần sau ghép lại.
- Cuối tuần: review chéo contract với cả nhóm; list quyền IAM (mục 3.9) gửi Nguyên.

### Tiêu chí hết tuần 1 (khớp M1)

- [ ] POC transcode một video mp4 ra HLS 360p/720p + thumbnail, phát được cục bộ
- [ ] Worker skeleton nhận message từ LocalStack và ghi `PROCESSING` vào DynamoDB
- [ ] Lệnh chạy + env đã giao cho Lưu làm Dockerfile
- [ ] `contracts/` không còn mục nào worker phụ trách bị treo

## Tuần 2 — Sprint 2: Pipeline hoàn chỉnh + độ tin cậy

### Mục tiêu
Epic **A4 xong** (tiêu chí: `make up`, upload video mẫu → `COMPLETED`, đủ assets) và **A5 xong** (heartbeat, idempotency, SIGTERM, DLQ).

### Việc cụ thể

| # | Việc | Ước tính | Ghi chú |
|---|---|---|---|
| 2.1 | `validate`: ffprobe wrapper + bảng giới hạn từ env; unit test với output ffprobe giả (json mẫu) | 0,5 pd | |
| 2.2 | `transcode`: build lệnh ffmpeg từ mục 3.5, timeout 15 phút, exit code → errorCode | 0,75 pd | |
| 2.3 | `job`: ghép pipeline đủ 11 bước (mục 3.3), cleanup bằng defer | 0,5 pd | |
| 2.4 | Upload output đúng Content-Type + sinh `master.m3u8`; ghi `assets` đầy đủ | 0,5 pd | |
| 2.5 | **Chạy e2e local**: `make up` → upload → `COMPLETED` → phát `/media/...`; sửa lỗi vặt cho tới khi pass | 0,75 pd | Cần Dockerfile của Lưu và `POST confirm` của Phương |
| 2.6 | **Heartbeat** gia hạn visibility ~120s/lần; kiểm tra với job giả dài | 0,5 pd | A5 |
| 2.7 | **Idempotency** đầy đủ: bỏ qua đã COMPLETED; `ConditionExpression` thắng/thua đúng kịch bản | 0,25 pd | A5 |
| 2.8 | **SIGTERM**: không nhận job mới; trả message đang chạy (đặt visibility ~30s); dọn tạm | 0,5 pd | A5 |
| 2.9 | **Chaos**: hoàn thiện `local/scripts/chaos-kill-worker.sh` — kill giữa chừng → job nhận lại → `COMPLETED`; job lỗi 3 lần → DLQ | 0,5 pd | A5; `make chaos` pass |

### Điểm phụ thuộc

- Dockerfile worker (Lưu, cuối Sprint 1) — nếu trễ thì e2e tạm chạy bằng `go run` + LocalStack, ghép Docker sau.
- `POST confirm` gửi SQS (Phương, A3 Sprint 2) — trước đó test bằng cách push message tay vào queue.

### Tiêu chí hết tuần 2 (khớp M2)

- [ ] `make e2e` pass: upload video hợp lệ → `COMPLETED` + đủ assets trên S3 + phát được
- [ ] Video quá giới hạn (6 phút / 1440p / đuôi giả) → đúng `FAILED_VALIDATION` + errorCode
- [ ] Kill worker giữa transcode → job được nhận lại và hoàn tất; không mất job
- [ ] Job lỗi 3 lần → message ở DLQ
- [ ] Gửi SIGTERM giữa job → worker thoát gọn, message quay về queue
- [ ] **M2: pipeline end-to-end chạy trên AWS** (image lên ECR, ASG chạy được — phần deploy do Nguyên, Vũ hỗ trợ debug worker)

> M2 là **điểm quyết định của cả nhóm**: chưa có pipeline chạy trên AWS thì hoãn toàn bộ P1. Nếu tuần 2 thiếu, tuần 3 ưu tiên dồn cho việc này trước mọi thứ khác.

## Tuần 3 — Sprint 3: Cứng hóa, quan sát, chuẩn bị benchmark

### Mục tiêu
Worker đạt chất lượng để nhóm Cloud làm C5 (scaling) và để A8 (benchmark) khởi động ngay đầu Sprint 4; đồng thời hỗ trợ chạy thật trên AWS.

### Việc cụ thể

| # | Việc | Ước tính | Ghi chú |
|---|---|---|---|
| 3.1 | **Metric + log chuẩn**: phát `jobs_completed`, `jobs_failed`, `processing_duration`, `queue_wait_duration`, `retry_count`; log JSON có jobId/videoId | 0,5 pd | Cần cho dashboard C5 và benchmark A8 |
| 3.2 | **Thử trên AWS thật**: worker chạy qua ASG (image từ ECR), xử lý vài job thật; sửa lỗi cấu hình/IAM phát sinh | 0,75 pd | Cùng Nguyên (C3) |
| 3.3 | **Phối hợp C5**: cung cấp số liệu `processing_duration` thật để Nguyên chốt target `BacklogPerInstance`; kiểm tra scale-in protection không giết máy đang transcode; thử min 0 (khởi động nguội có nhận job đúng) | 0,5 pd | M3: worker scale 1 → 2 và giảm khi hết tải |
| 3.4 | Hiệu chỉnh transcode (nếu cần): chỉnh `hls_time`, bitrate sau khi xem kích thước output và thời gian xử lý thật trên máy EC2 | 0,25 pd | |
| 3.5 | **Chuẩn bị A8**: chốt bộ video benchmark, ghi kịch bản đo baseline (1 worker) để Sprint 4 chạy liền; đo thử 1 lần lấy số liệu ban đầu | 0,5 pd | Cùng Lưu |
| 3.6 | Ổn định + sửa lỗi từ feedback tuần 2-3; cập nhật lại tài liệu `docs-worker/` theo thực tế code | 0,5 pd | Tài liệu phải khớp code trước khi báo cáo |

### Tiêu chí hết tuần 3 (khớp M3)

- [ ] Worker xử lý job ổn định trên AWS; log/metric hiện trên CloudWatch
- [ ] Đã bàn giao số liệu processing duration để chốt scaling target
- [ ] Thử nghiệm scale 1 → 2 → 1 thành công (phần ASG của Nguyên, worker không cản trở)
- [ ] Bộ video + kịch bản benchmark sẵn sàng cho Sprint 4
- [ ] `docs-worker/` cập nhật theo code thật (không còn khác biệt "trên giấy")

## Sau 3 tuần (ngoại lệ, để đối chiếu)

Sprint 4 worker chỉ còn **hỗ trợ A8** (benchmark 1 vs 2 worker, kịch bản worker lỗi trên AWS — Lưu chủ trì) và **R1** (số liệu, hình vẽ cho báo cáo). Không có tính năng mới ở worker sau tuần 3, trừ bug fix.

## Rủi ro và phương án

| Rủi ro | Xác suất | Phương án |
|---|---|---|
| FFmpeg command không ra HLS đúng ý (filter `split` + 2 output) | Trung bình | Làm POC ngay ngày đầu tuần 1; nếu bế tắc, fallback chạy 2 lần FFmpeg (chậm hơn nhưng đúng) — chấp nhận được cho MVP |
| LocalStack/Dockerfile chậm (M0, C0) | Trung bình | Phát triển với mock interface + ffprobe/ffmpeg cục bộ (việc 1.2, 1.3 không phụ thuộc ai) |
| `POST confirm` (Phương) chưa xong ở tuần 2 | Trung bình | Test consumer bằng cách push message tay vào SQS; ghép khi có |
| Spot thu hồi giữa demo/benchmark | Thấp | SIGTERM đã xử lý từ tuần 2; benchmark dùng on-demand theo kế hoạch chung |
| Đĩa EC2 nhỏ đầy vì file tạm | Thấp | Cleanup defer + quét thư mục mồ côi lúc khởi động (mục 3.7) |
| Trễ M2 | — | Tuần 3 dồn toàn bộ cho pipeline trên AWS; cắt 3.4, 3.5 (benchmark rơi sang đầu Sprint 4) |
