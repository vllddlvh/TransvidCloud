# 5. Hợp đồng giao tiếp của Worker

Worker **không expose HTTP API**. Tài liệu này mô tả toàn bộ "giao diện" worker dùng để nói chuyện với phần còn lại của hệ thống: SQS (đầu vào), DynamoDB (trạng thái), S3 (dữ liệu), log/metric (quan sát), biến môi trường (cấu hình). Nguồn sự thật là `docs/contracts/`; file này triển khai chi tiết hơn từ góc nhìn worker và là nơi đối chiếu khi tích hợp.

## 5.1. Đầu vào: message SQS

Schema đầy đủ: `docs/contracts/sqs-job-message.schema.json`.

```json
{
  "schemaVersion": 1,
  "jobId": "job_9f2c1b",
  "videoId": "vid_4a77e1",
  "projectId": "prj_1c05d9",
  "inputKey": "prj_1c05d9/vid_4a77e1/source.mp4",
  "requestedAt": "2026-10-19T09:15:30Z"
}
```

Quy ước worker tuân thủ khi nhận:

| Quy tắc | Xử lý |
|---|---|
| `schemaVersion` khác 1 | Log `UNSUPPORTED_SCHEMA`, **xóa message** (không retry được — message dạng này mãi mãgiờ sai) |
| Thiếu trường bắt buộc | Log `INVALID_MESSAGE`, xóa message |
| `inputKey` không khớp `{projectId}/{videoId}/source.{ext}` | Log cảnh cáo nhưng vẫn cố xử lý theo `inputKey` |
| `jobId` không an toàn (chứa `..`, dấu phân cách, quá 128 ký tự) | Log `INVALID_MESSAGE`, **xóa message**; không dùng ID làm tên thư mục |
| Message attributes | Đọc `ApproximateReceiveCount` để biết lần nhận thứ mấy (body không sửa được, nguồn đáng tin hơn `attemptCount`) |
| Nhận lại lần 3 trở đi | Vẫn xử lý bình thường; khi lỗi lần nữa, SQS redrive message sang DLQ (queue tự lo, worker không cần biết) |

`jobId` phải khớp `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` (chữ, số, `.`, `_`, `-`). Đây là kiểm tra phòng vệ đường dẫn: worker ghép `TVC_TMP_DIR/<jobId>` và chỉ dọn trong vùng tạm của mình, nên ID lạ bị coi là poison message thay vì tạo/xóa nhầm thư mục.

Tham số ReceiveMessage: `WaitTimeSeconds=20` (long polling), `MaxNumberOfMessages=1` (một job một lúc).

## 5.2. Trạng thái: các thao tác DynamoDB

Bảng `tvc-{env}-videos`, key `videoId`. Worker chỉ dùng 3 thao tác.

### 5.2.1. Đọc (idempotency check)

```text
GetItem: { "videoId": vid }
cần: status
```

Nếu `status = COMPLETED`, worker bỏ qua job và không gọi `MarkProcessing`, nên `attemptCount` **không tăng**. Số lần nhận thật của message lấy từ `ApproximateReceiveCount`; `attemptCount` chỉ đếm số lần job thực sự bắt đầu xử lý lại (chuyển `PROCESSING`).

### 5.2.2. Nhận job — chuyển `PROCESSING`

```text
UpdateItem
Key: { videoId }
UpdateExpression:  SET #s = :processing,
                    attemptCount = if_not_exists(attemptCount, 0) + :one,
                    startedAt = :now,
                    updatedAt = :now
                    REMOVE errorCode, completedAt
ConditionExpression: #s <> :completed OR attribute_not_exists(#s)
ExpressionAttributeNames:  { "#s": "status" }
```

`REMOVE errorCode, completedAt` xóa dấu vết lỗi/kết thúc cũ khi job được nhận lại (retry sau `FAILED_*`), để API không hiển thị `errorCode` cũ trong lúc video đang `PROCESSING` lần nữa.

Nếu điều kiện sai (ConditionalCheckFailedException): đọc lại item; nếu `status = COMPLETED` → xóa message, bỏ qua job. Nếu điều kiện thắng: video giờ ở `PROCESSING`, worker sở hữu job này.

### 5.2.3. Kết thúc — `COMPLETED` hoặc `FAILED_*`

```text
UpdateItem
Key: { videoId }
UpdateExpression:  SET #s = :final,
                    errorCode = :code,          -- chỉ khi FAILED_*
                    assets = :assets,           -- chỉ khi COMPLETED
                    completedAt = :now,
                    updatedAt = :now
                    REMOVE errorCode            -- chỉ khi COMPLETED
ConditionExpression: #s <> :completed
```

`:final` là một trong:

| Giá trị | Khi nào | `errorCode` kèm |
|---|---|---|
| `COMPLETED` | transcode + upload xong | — (kèm `assets`) |
| `FAILED_VALIDATION` | ffprobe phát hiện vi phạm giới hạn | `NOT_A_VIDEO` \| `CODEC_UNSUPPORTED` \| `DURATION_EXCEEDED` \| `HEIGHT_EXCEEDED` |
| `FAILED_TRANSCODE` | FFmpeg exit ≠ 0 hoặc timeout | `FFMPEG_EXIT_<code>` \| `FFMPEG_TIMEOUT` |
| `FAILED_STORAGE` | lỗi đọc/ghi S3 | `S3_GET_FAILED` \| `S3_PUT_FAILED` |

Mã chẩn đoán nội bộ (chưa nằm trong bảng contract, **chờ Phương chốt**): `DDB_GET_FAILED`, `DDB_UPDATE_FAILED`, `HEARTBEAT_START_FAILED`, `FFMPEG_START_FAILED`, `LOCAL_FS_FAILED`, `MASTER_WRITE_FAILED`. Hiện `LOCAL_FS_FAILED` (lỗi tạo/ghi thư mục tạm) và `MASTER_WRITE_FAILED` (lỗi ghi master playlist) có thể được ghi vào `errorCode` cùng `FAILED_STORAGE`/`FAILED_TRANSCODE`; các mã còn lại chủ yếu xuất hiện trong log `job_failed` khi chưa ghi được trạng thái. Không thêm mã mới ngoài danh sách này trước khi contract được review.

`assets` khi `COMPLETED` (khớp `docs/contracts/dynamodb-tables.md`):

```json
{
  "hls":       "prj_1c05d9/vid_4a77e1/hls/master.m3u8",
  "hls360":    "prj_1c05d9/vid_4a77e1/hls/360p/index.m3u8",
  "hls720":    "prj_1c05d9/vid_4a77e1/hls/720p/index.m3u8",
  "thumbnail": "prj_1c05d9/vid_4a77e1/thumb/default.jpg"
}
```

> *(chờ chốt)* field `assets` lưu key S3 hay URL đầy đủ — hiện contract ghi "map: `hls`, `hls360`, `hls720`, `thumbnail`"; đề xuất lưu key và để API/frontend ghép `/media/...`, vì worker không nên biết domain phát.

**Ranh giới ghi với API** (tránh hai bên ghi đè — đã ghi trong [`docs/contracts/dynamodb-tables.md`](../contracts/dynamodb-tables.md)): worker **không ghi** `title`, `originalKey`, `createdAt`, và không tự chuyển `UPLOADING -> PENDING`. IAM của worker cũng không cho phép ghi các bảng khác.

## 5.3. Dữ liệu: các thao tác S3

| Thao tác           | Key                                                            | Content-Type                    |
| ------------------ | -------------------------------------------------------------- | ------------------------------- |
| GetObject (input)  | `{projectId}/{videoId}/source.{ext}`                           | —                               |
| PutObject (output) | `{projectId}/{videoId}/hls/master.m3u8`                        | `application/vnd.apple.mpegurl` |
| PutObject          | `{projectId}/{videoId}/hls/360p/index.m3u8`, `720p/index.m3u8` | `application/vnd.apple.mpegurl` |
| PutObject          | `{projectId}/{videoId}/hls/{360p,720p}/seg_%03d.ts`            | `video/mp2t`                    |
| PutObject          | `{projectId}/{videoId}/thumb/default.jpg`                      | `image/jpeg`                    |

PutObject đặt thêm: `Cache-Control: public, max-age=31536000, immutable` cho `.ts` (key ổn định, không đổi nội dung) và `max-age=60` cho `.m3u8` *(chờ chốt cùng C4/CloudFront)*.

## 5.4. Điều khiển message SQS

| Thao tác | Khi nào | Tham số |
|---|---|---|
| `ReceiveMessage` | vòng lặp chính | `WaitTimeSeconds=20`, `MaxNumberOfMessages=1` |
| `ChangeMessageVisibility` | heartbeat mỗi 120s khi job chạy | `VisibilityTimeout=300` (đặt lại toàn bộ) |
| `ChangeMessageVisibility` | khi SIGTERM, job đang chạy | `VisibilityTimeout=30` (trả message về queue sớm) |
| `DeleteMessage` (ACK) | chỉ khi `COMPLETED` hoặc `FAILED_VALIDATION` hoặc đã `COMPLETED` từ trước | kèm `ReceiptHandle` |

Bảng quyết định "xóa hay giữ message":

| Kết quả job | Xóa message? | Lý do |
|---|---|---|
| `COMPLETED` | ✅ xóa | Xong |
| `FAILED_VALIDATION` | ✅ xóa | Lỗi đầu vào, retry vô ích |
| `FAILED_TRANSCODE` | ❌ giữ | Có thể là lỗi tạm thời → SQS giao lại |
| `FAILED_STORAGE` | ❌ giữ | Lỗi tạm thời |
| Đã `COMPLETED` từ trước (idempotency) | ✅ xóa | Dọn message trùng |
| Message sai schema | ✅ xóa | Poison message, giữ lại chỉ gây vòng lặp vô hạn rồi vào DLQ |

Quy tắc khi ACK/ghi trạng thái lỗi:

- **Chưa ghi được kết quả thì không ACK**: nếu `MarkFailed` lỗi (DynamoDB không truy cập được), message được giữ để retry; worker không tuyên bố job đã kết thúc.
- **Đã `COMPLETED` nhưng ACK lỗi**: message sẽ được giao lại; lần nhận sau thấy `COMPLETED` thì bỏ qua transcode và thử ACK lại. Không ghi lùi sang `FAILED_*`.
- **SIGTERM**: worker dừng nhận job, hủy job đang chạy, dừng heartbeat rồi gọi `ChangeMessageVisibility(30)` bằng context riêng có timeout. Nếu release lỗi, worker log `message_release_failed`; message chỉ quay lại theo visibility còn lại, **không được báo là đã trả sau 30s**.
- **Heartbeat lỗi**: retry có giới hạn trong khoảng an toàn; hết lượt thì hủy job với lý do mất quyền sở hữu, không ACK và không ghi `FAILED_*`. Message quay lại queue khi hết visibility.
- **Chưa có lease/owner token**: `status <> COMPLETED` chỉ chặn ghi đè trạng thái cuối, **không** bảo đảm một worker duy nhất. Hai worker vẫn có thể cùng transcode/ghi output cùng key; lần ghi `COMPLETED` đầu tiên thắng, lần sau nhận `ErrAlreadyCompleted` và ACK message trùng. Đây là giới hạn đã biết, chờ review contract với Phương trước khi thêm cơ chế ownership.

## 5.5. Log (định dạng chuẩn để CloudWatch query)

Một dòng JSON mỗi bản ghi; `jobId`, `videoId`, `projectId` có mặt ở mọi dòng trong phạm vi một job:

```json
{"ts":"2026-10-19T09:16:02Z","level":"info","service":"worker","jobId":"job_9f2c1b","videoId":"vid_4a77e1","projectId":"prj_1c05d9","msg":"job_finished","status":"COMPLETED","durationMs":48210,"attempt":1,"ffmpegMs":41003,"bytesIn":104857600,"bytesOut":38211000}
```

Các sự kiện bắt buộc phải có (msg): `job_received`, `skipped_completed`, `mark_processing`, `downloaded`, `validated` (kèm duration/height/codec), `transcode_started`, `transcode_done`, `uploaded`, `job_finished`, `job_failed` (kèm errorCode), `shutdown` (SIGTERM).

Sự kiện reliability bổ sung: `invalid_message` (kèm code `INVALID_MESSAGE`/`UNSUPPORTED_SCHEMA`), `message_released` (kèm `visibilitySeconds`), `message_release_failed`, `job_ownership_lost` (heartbeat hết retry), `job_completed_without_ack` (đã ghi `COMPLETED` nhưng bị ngắt trước ACK). Các log này không chứa receipt handle.

## 5.6. Metric (namespace `TransVidCloud`)

| Metric | Đơn vị | Dimension | Phát khi |
|---|---|---|---|
| `jobs_completed` | count | — | ghi COMPLETED |
| `jobs_failed` | count | `errorCode` | ghi FAILED_* |
| `processing_duration` | ms | — | kết thúc job (cả thành công lẫn thất bại) |
| `queue_wait_duration` | ms | — | nhận message ( = now − requestedAt) |
| `retry_count` | count | — | nhận lại lần ≥ 2 |
| `worker_utilization` | percent | — | phần trăm thời gian có job đang chạy (đo chu kỳ, phục vụ scale + report) |

Local: `cloudwatch:PutMetricData` no-op (LocalStack không cần); cloud: phát thật. Không tạo metric tùy chỉnh ngoài danh sách này mà không báo nhóm Cloud (C5 phụ thuộc danh sách này để làm dashboard).

## 5.7. Cấu hình: biến môi trường hoàn chỉnh

Xem bảng đầy đủ ở [[3. Architecture]] mục 3.8. Tóm tắt bắt buộc vs tùy chọn:

- **Bắt buộc** (thiếu thì thoát lúc khởi động): `TVC_INPUT_BUCKET`, `TVC_OUTPUT_BUCKET`, `TVC_JOBS_QUEUE_URL`, `TVC_DDB_VIDEOS`, `AWS_REGION`.
- **Tùy chọn có mặc định**: `AWS_ENDPOINT_URL`, `MAX_DURATION_SECONDS=300`, `MAX_HEIGHT_PIXELS=1080`, `MAX_UPLOAD_BYTES=209715200`, `TVC_TMP_DIR=/tmp/tvc`, `TVC_FFMPEG_TIMEOUT=15m`, `TVC_HEARTBEAT_INTERVAL=120s`, `TVC_VISIBILITY_TIMEOUT=300s`.
- Worker **không đọc** secret nào (không JWT, không API key) — IAM role là tất cả danh tính nó cần.

Ràng buộc cấu hình được kiểm lúc khởi động: `TVC_HEARTBEAT_INTERVAL > 0`, `TVC_VISIBILITY_TIMEOUT > 0`, `TVC_HEARTBEAT_INTERVAL * 2 <= TVC_VISIBILITY_TIMEOUT` (đủ ít nhất hai lần gia hạn trong một cửa sổ visibility), `TVC_FFMPEG_TIMEOUT > 0`. `TVC_TMP_DIR` phải là đường dẫn tuyệt đối, không phải `/`, `/tmp`, `/var`, home hay thư mục dùng chung; worker ghi marker `.tvc-worker-tmp` và chỉ dọn các mục con khi marker tồn tại. `MAX_UPLOAD_BYTES` vẫn do API enforce; worker chỉ ghi nhận `bytesIn`, không tự thêm mã lỗi dung lượng.

## 5.8. Mã thoát tiến trình

| Exit code | Ý nghĩa | Hệ thống phản ứng |
|---|---|---|
| 0 | Đóng gọn (SIGTERM xử lý xong, hoặc nhận lệnh dừng) | container/máy bị thay thế bình thường |
| 1 | Lỗi cấu hình lúc khởi động (thiếu env) | container restart rồi lại fail — alert qua log; sửa env trong Terraform/Parameter Store |
| 2 | Panic không khống chế được | container restart (restart policy); job đang giữ sẽ tự quay về queue khi hết visibility |

## 5.9. Trace một job thành công (bản đối chiếu khi tích hợp)

Chuỗi sự kiện mong đợi, dùng để soát lỗi khi ghép module:

```text
API:      POST confirm -> DynamoDB status=PENDING, SQS send (schemaVersion=1)
Worker:   job_received      jobId=job_9f2c1b attempt=1
Worker:   mark_processing   status=PROCESSING
Worker:   downloaded        bytesIn=104857600
Worker:   validated         duration=213s height=720 codec=h264
Worker:   transcode_started
Worker:   (heartbeat mỗi 120s, không log từng lần — log 1 dòng nếu fail)
Worker:   transcode_done    ffmpegMs=41003
Worker:   uploaded          objects=34 bytesOut=38211000
Worker:   job_finished      status=COMPLETED
SQS:      message bị xóa (ACK)
S3:       hls/master.m3u8, hls/360p/*, hls/720p/*, thumb/default.jpg tồn tại đúng Content-Type
DynamoDB: status=COMPLETED, assets đầy đủ, attemptCount=1
Frontend: GET video -> COMPLETED -> hls.js phát /media/.../master.m3u8
```
