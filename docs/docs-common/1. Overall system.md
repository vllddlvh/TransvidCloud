# 1. Tổng quan hệ thống TransVidCloud

## 1.1. Bài toán và sản phẩm

TransVidCloud là **nền tảng xử lý video trên AWS** (đồ án môn Cloud Computing): upload video nặng, xử lý bất đồng bộ, co giãn worker, phân phối HLS. Không phải clone YouTube; trọng tâm là chứng minh kiến trúc cloud.

Hai cách dùng, **một lõi xử lý**:

| Cách dùng | Ai | Làm gì |
|---|---|---|
| **SaaS Web** | Người dùng cuối | Đăng nhập, project, upload, theo dõi trạng thái, phát HLS, lấy link/embed |
| **Developer API** | Ứng dụng bên ngoài (vd. E-learning) | API key, presigned upload, submit job, poll status, lấy assets |

Backend Spring Boot phục vụ cả hai; **không** chạy FFmpeg và **không** proxy byte video lớn qua HTTP.

## 1.2. Sơ đồ thành phần (logical)

```text
                    ┌─────────────┐     ┌──────────────────┐
  Người dùng SaaS ──┤  React Web  │     │  App bên ngoài   │
                    └──────┬──────┘     └────────┬─────────┘
                           │    JWT / API key     │
                           └──────────┬───────────┘
                                      v
                           ┌──────────────────────┐
                           │  API (Spring Boot)   │
                           │  metadata, presign,  │
                           │  confirm, status     │
                           └───┬────────┬────┬────┘
                               │        │    │
                          DynamoDB    S3   SQS
                               │        │    │
                               │        │    v
                               │        │  Worker (Go+FFmpeg)
                               │        │    transcode HLS
                               │        └─── upload output
                               └──────────── cập nhật trạng thái
```

**Phân phối nội dung:** trình duyệt upload **thẳng S3 input** (presigned PUT). Phát video qua **CDN/edge** (`/media/*` → bucket output). API qua **edge** (`/api/*`).

## 1.3. Luồng nghiệp vụ cốt lõi (happy path)

```text
1. Client: POST /projects/{id}/videos (khai báo size, content-type)
2. API: tạo bản ghi UPLOADING, trả presigned URL → bucket input
3. Client: PUT file lên S3 (không qua API)
4. Client: POST /videos/{id}/confirm
5. API: HeadObject, UPLOADING → PENDING, gửi message SQS
6. Worker: nhận job → PROCESSING → FFmpeg → upload HLS 360p/720p + thumbnail
7. Worker: DynamoDB COMPLETED + assets; ACK message SQS
8. Client: GET /videos/{id} → phát master.m3u8 qua /media/...
```

Trạng thái video: xem [video-state-machine.md](../contracts/video-state-machine.md) (DRAFT).

## 1.4. Local vs AWS — cùng code, khác cấu hình

| Khía cạnh | Local (dev) | AWS (dev/demo) |
|---|---|---|
| Object storage, queue, DB | LocalStack | S3, SQS, DynamoDB thật |
| API + Worker | Docker Compose (khi có Dockerfile) hoặc chạy IDE | EC2 API + ASG Worker (Spot) |
| Một domain cho web/API/media | nginx `localhost:8000` | CloudFront (+ Tunnel cho API origin) |
| Credential | `test` / `test` | IAM role trên EC2 |
| Endpoint AWS SDK | `AWS_ENDPOINT_URL=http://localhost:4566` | **Không set** (SDK mặc định) |
| Presigned URL cho browser | `S3_PRESIGN_ENDPOINT=http://localhost:4566` | Endpoint S3 public |

**Hai biến S3 quan trọng:** backend trong container gọi `localstack:4566`, trình duyệt cần `localhost:4566` — xem [LOCAL_AND_CICD](../introduction/2.%20LOCAL_AND_CICD.md) mục 1.5.

Tên tài nguyên local: tiền tố `tvc-local-*`. Cloud: `tvc-{env}-*`.

## 1.6. Phạm vi MVP (P0) — nhắc nhanh

- Video output: **360p + 720p + HLS + thumbnail** (1080p = P1 nếu cắt scope).
- Giới hạn upload: **200 MB, 5 phút, tối đa 1080p** — [upload-limits.md](../contracts/upload-limits.md).
- DynamoDB duy nhất cho metadata — [ADR 0001 — DynamoDB only](5.%20Architecture%20decisions.md).
- Webhook, CI/CD Terraform đầy đủ, domain tùy chỉnh: **P1 / ngoài cam kết nộp tuần 10**.
