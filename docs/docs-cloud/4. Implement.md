# 4. Implement — Triển khai từ local lên AWS

## 1. Mục tiêu và trạng thái xuất phát

Thực hiện theo thứ tự: **local infrastructure → ứng dụng local → kiểm thử → AWS dev → edge/scaling → thực nghiệm → demo**. Người thực hiện chính: Lưu cho local/dữ liệu/mạng/E2E, Nguyên cho IAM/compute/edge/deploy/quan sát. Mốc bàn giao theo [Timelines](2.%20Timelines.md), cấu hình theo [Designs](3.%20Designs.md).

Rà soát repo ngày **21/10/2026**:

| Hạng mục | Hiện trạng | Ý nghĩa khi làm theo hướng dẫn |
|---|---|---|
| Compose, `.env.example`, init/smoke LocalStack | Đã có cấu hình/script | Có thể bắt đầu dựng hạ tầng local; vẫn cần chạy để kiểm chứng |
| Backend, worker, frontend | Hiện chỉ có README và hướng dẫn testdata | Chưa build hoặc chạy được full stack |
| `infra/terraform` | README mô tả module/env, chưa có `.tf` | Phải viết module/root configuration trước khi plan/apply |
| `make test`, CI | Bỏ qua module chưa có source/manifest | Kết quả xanh khi bỏ qua không chứng minh ứng dụng đạt kiểm thử |
| `make e2e` | Chỉ phụ thuộc `up` và `smoke` | Chưa có kịch bản upload/confirm/poll/playback |
| `make chaos` | Script chỉ in thông báo chưa triển khai | Chưa kiểm chứng retry hoặc DLQ |
| Script deploy API | Gửi SSM command, còn TODO env/secret/Tunnel/health/rollback | Cần hoàn thiện trước deploy chính thức |
| Script worker | Cập nhật SSM tag và gọi Instance Refresh | Cần Launch Template/user-data và bước theo dõi kết quả |
| Workflow Deploy | Build/push/deploy theo `github.sha`, chọn env | Cần source, quyền, tài nguyên và sửa các khoảng trống ở mục 8 |

Các bước dưới đây là runbook triển khai; không phải nhật ký xác nhận hạ tầng đã được dựng.

## 2. Chuẩn bị máy local — C0, ngày 1–3

Trên Windows dùng Docker Desktop với WSL2. Các khối lệnh `bash` chạy trong **Git Bash hoặc WSL**, tại root repo, không dán nguyên cú pháp gán biến vào PowerShell. Cần Git, Docker Compose và GNU Make nếu dùng `make`; Git Bash không mặc định có Make.

Chạy trực tiếp ứng dụng cần JDK 21, Go theo `go.mod` khi được bổ sung, FFmpeg/ffprobe và Node theo cấu hình frontend/CI (khung CI hiện dùng Node 20). Nhóm Cloud cần AWS CLI và Terraform >= 1.10 cho giai đoạn AWS. Chốt phiên bản thực tế khi mã ứng dụng được đưa vào repo.

```bash
docker version
docker compose version
make --version
cp .env.example .env
```

Chỉ copy nếu chưa có `.env`, tránh ghi đè cấu hình cá nhân. Điền `LOCALSTACK_AUTH_TOKEN` theo image đang dùng; sau lần chạy ổn định ghim `LOCALSTACK_IMAGE` vào tag/digest nhóm đã kiểm chứng. Giữ credential `test/test` cho local, không đặt credential AWS thật trong `.env` dùng chung.

## 3. Dựng và kiểm tra hạ tầng local — M0

```bash
make infra
docker compose ps
docker compose logs --tail=100 localstack
make smoke
```

Nếu chưa có Make:

```bash
docker compose up -d localstack
bash local/scripts/smoke-test.sh
```

Chờ LocalStack ready và script `01-resources.sh` hoàn tất rồi chạy smoke. Smoke hiện kiểm tra **tên tồn tại** của ba bucket, hai queue và bốn bảng:

- Bucket: `tvc-local-frontend`, `tvc-local-input`, `tvc-local-output`.
- Queue: `tvc-local-jobs`, `tvc-local-jobs-dlq`.
- Table: `tvc-local-users`, `tvc-local-projects`, `tvc-local-apikeys`, `tvc-local-videos`.

Smoke chưa xác nhận đầy đủ thuộc tính. Kiểm tra bổ sung CORS, GSI và cấu hình queue:

```bash
docker compose exec -T localstack awslocal s3api get-bucket-cors --bucket tvc-local-input
docker compose exec -T localstack awslocal dynamodb describe-table --table-name tvc-local-videos
QUEUE_URL=$(docker compose exec -T localstack awslocal sqs get-queue-url --queue-name tvc-local-jobs --query QueueUrl --output text)
docker compose exec -T localstack awslocal sqs get-queue-attributes --queue-url "$QUEUE_URL" --attribute-names All
```

Đối chiếu visibility 300, long polling 20, redrive maxReceiveCount 3 và GSI theo [contract](../../contracts/dynamodb-tables.md). Init hiện chưa cài lifecycle input 7 ngày; bổ sung khi hoàn thiện C0/C1 và xác minh riêng trên AWS, không suy ra từ smoke.

**Đạt M0 khi:** log init không lỗi, đủ tài nguyên và backend/worker do App chạy từ IDE kết nối được LocalStack. Lưu ghi kết quả trên máy từng thành viên.

## 4. Hoàn thiện và chạy ứng dụng local — cuối Sprint 1 đến Sprint 2

### 4.1. Các phần phải bổ sung trước `make up`

| Việc | Chủ và điều kiện |
|---|---|
| Source backend/worker/frontend | Phương/Vũ cung cấp build/run command, manifest và health endpoint |
| Dockerfile backend | Lưu viết, Phương review; build artifact và runtime phù hợp Java |
| Dockerfile worker | Lưu viết, Vũ review; có FFmpeg/ffprobe, thư mục tạm và xử lý tín hiệu dừng |
| Cấu hình runtime | App/Cloud thống nhất bucket, queue, table, media URL; truyền rõ vào Compose |
| Frontend dev server | Vũ cung cấp script; server nghe trên địa chỉ host mà nginx container truy cập được, cổng 5173 |

Compose **không tự chuyển toàn bộ `.env` vào container**; hiện mới truyền một số biến. Trước chạy full stack, thêm `environment`/cơ chế cấp cấu hình phù hợp cho các biến tài nguyên trong `.env.example`. Tên `TVC_*` trong kiến trúc cũ chưa được nối với tên `S3_BUCKET_*`, `SQS_QUEUE_NAME`, `DDB_TABLE_PREFIX` hiện tại; phải thống nhất với App, không giả định cả hai đều hoạt động.

### 4.2. Endpoint theo vị trí chạy

| Cấu hình | Chạy IDE trên host | Trong container | AWS |
|---|---|---|---|
| `AWS_ENDPOINT_URL` | `http://localhost:4566` | `http://localstack:4566` | Bỏ override/để trống theo code |
| `S3_PRESIGN_ENDPOINT` | `http://localhost:4566` | `http://localhost:4566` | Endpoint S3 thật qua SDK |
| Credential | `test/test` | `test/test` | Instance profile |
| Tên tài nguyên | `tvc-local-*` | `tvc-local-*` | Giá trị thực từ Terraform/cấu hình |
| Media URL | `/media/...` qua nginx | Backend trả URL cho browser | `/media/...` qua CloudFront |

Backend cần dùng path-style addressing cho S3 local. Host trong presigned URL phải truy cập được từ trình duyệt; không sửa host của URL sau khi ký để chữa lỗi.

### 4.3. Chạy full stack sau khi đủ điều kiện

Khởi động frontend bằng lệnh App đã chốt trên host cổng 5173, sau đó:

```bash
make up
docker compose --profile full ps
make logs S=backend
```

Lệnh tương đương: `docker compose --profile full up -d --build`. Truy cập `http://localhost:8000`; `/api/*` tới backend, `/media/*` tới output bucket, `/` tới frontend dev server trên host. Frontend không phải service Compose hiện tại.

```bash
make worker-scale N=2
docker compose logs --tail=100 worker
```

Nhiều container local kiểm tra việc cùng nhận queue; đây chưa phải thử nghiệm ASG. Compose chưa lưu bền LocalStack nên cần xem dữ liệu local là dữ liệu thử có thể mất khi container bị xóa.

## 5. Kiểm thử trước khi chuyển AWS

Lưu chủ trì hoàn thiện harness ở [tests/e2e](../../tests/e2e/README.md), App cung cấp payload theo [OpenAPI](../../contracts/openapi.yaml). Contract hiện còn DRAFT; không tự viết request body giả rồi coi là lệnh E2E dùng được.

| Kịch bản | Kết quả bắt buộc |
|---|---|
| Luồng hợp lệ | Đăng ký/đăng nhập → project → tạo video/presigned URL → PUT S3 → confirm → poll `COMPLETED` |
| Output | Master playlist, rendition 360p/720p, segment và thumbnail tồn tại; phát qua nginx được |
| Vượt giới hạn | Khai báo/file vượt 209715200 byte bị chặn; input quá 300s/1080p bị worker từ chối đúng contract |
| Confirm sai | Object thiếu hoặc dung lượng sai không được đẩy thành job hợp lệ |
| Giao message trùng | Không ghi đè `COMPLETED`; không có hai kết quả mâu thuẫn |
| Kill worker | Job đang xử lý được giao lại sau visibility timeout; hoàn thành hoặc có lỗi rõ ràng |
| Lỗi lặp lại | Theo dõi receive count, message vào DLQ; không mất việc im lặng |

Hiện `make e2e` chưa có runner và `make chaos` chưa có assertions. Cần nối runner vào Makefile và trả exit code thất bại khi sai, trước khi dùng hai lệnh làm điều kiện merge/deploy. Harness tương lai nhận `BASE_URL=http://localhost:8000` hoặc URL AWS; chưa có lệnh runner cloud thực tế trong repo.

**Gate lên AWS:** contract review xong, image build được, E2E và retry local có bằng chứng, schema/env thống nhất. Cloud có thể dựng trước hạ tầng dữ liệu/mạng ở Sprint 1, nhưng chưa đánh dấu ứng dụng sẵn sàng deploy khi thiếu các điều kiện trên.

## 6. Chuẩn bị AWS và Terraform — C1/C2

### 6.1. Account, quyền và chi phí

1. Chọn đúng account và `ap-southeast-1`; bật MFA, dùng phiên đăng nhập/profile phù hợp cho người vận hành.
2. Kiểm tra Service Quotas cho EC2 on-demand và Spot, loại máy dự kiến, quyền SSM/ECR và CloudFront.
3. Tạo cảnh báo ngân sách 25/50 USD sớm; xác nhận người nhận thông báo.
4. Chốt tag `Project=TransVidCloud`, `Env=dev/demo`, `ManagedBy` phản ánh đúng cách quản lý.

Trong terminal triển khai riêng, không nạp `.env` local:

```bash
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN
unset AWS_ENDPOINT_URL S3_PRESIGN_ENDPOINT
export AWS_PROFILE=tvc-dev
export AWS_REGION=ap-southeast-1
aws sts get-caller-identity
```

`tvc-dev` là tên profile ví dụ, phải thay bằng profile đã cấu hình. Kiểm tra account trả về trước bước tạo/sửa tài nguyên.

### 6.2. Bootstrap state và viết bốn module P0

Lưu tạo bucket state một lần theo phương án bootstrap riêng, bật versioning/mã hóa/chặn public, giới hạn quyền và cấu hình S3 lockfile. Ghi tên bucket, region, state key cho mỗi env; không ghi credential. Xem [Terraform S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3).

Tiếp theo viết `storage`, `queue`, `database`, `network`, root configuration cho `envs/dev`, provider version/lockfile và outputs cần bàn giao. `demo` dùng cùng module, state khác. Thêm `*.tfvars.example` chứa giá trị mẫu, không commit tfvars thật.

**Chỉ sau khi các file `.tf` và backend configuration đã tồn tại**, chạy từ root:

```bash
terraform fmt -check -recursive infra/terraform
terraform -chdir=infra/terraform/envs/dev init
terraform -chdir=infra/terraform/envs/dev validate
terraform -chdir=infra/terraform/envs/dev plan
```

Review đúng account/env, mọi thao tác tạo/thay thế/xóa, rồi chạy:

```bash
terraform -chdir=infra/terraform/envs/dev apply
terraform -chdir=infra/terraform/envs/dev output
```

Không dùng `make tf-plan` ở trạng thái repo hiện tại để chứng minh hạ tầng hợp lệ: target đã có nhưng root `dev` chưa được triển khai. Sau apply kiểm tra bucket private/CORS/lifecycle, queue/redrive, key/GSI và route; lưu outputs không nhạy cảm cho App.

## 7. Deploy đầu tiên lên AWS dev — C2/C3, M2

Thứ tự phụ thuộc thực tế:

| Bước | Việc và kiểm chứng |
|---|---|
| 1 | Tạo ECR `tvc-backend`/`tvc-worker`; build và push image theo commit SHA đã qua local |
| 2 | Tạo role/profile API và worker theo quyền trong Designs; cấp SSM/config/runtime |
| 3 | Chuẩn bị user-data: Docker, SSM Agent, ECR login/pull, cấu hình runtime, restart/log; chọn đúng kiến trúc CPU |
| 4 | Tạo API EC2 và Tunnel origin; health check trên máy rồi qua hostname Tunnel |
| 5 | Đặt worker image tag vào `/tvc/dev/worker/image-tag`; tạo Launch Template/ASG, ban đầu min/desired 1 để kiểm tra |
| 6 | Submit một video qua API, quan sát queue → worker → DynamoDB → S3 output; xác nhận `COMPLETED` |
| 7 | Kiểm tra quyền âm và lỗi: worker không ghi input; retry không làm mất job; log đủ ID |

Nếu CI/CD chưa sẵn sàng, dùng credential tạm của người triển khai để push ECR và script theo runbook. Tài nguyên ngoài bốn module P0 làm thủ công phải được ghi lại; không tạo một bản Terraform trùng tài nguyên đang có, cần import khi chuyển quản lý.

### 7.1. Tunnel trên EC2 API

Nguyên tạo remotely managed Tunnel, hostname `origin-api.<domain>` và route tới `http://localhost:8080`. Lưu token vào SSM SecureString `/tvc/dev/cloudflared/token`. Chạy `cloudflared` host network trên EC2 Linux; API chỉ publish `127.0.0.1:8080`.

Đọc token ở runtime, không đưa literal token vào tài liệu hoặc log; có thể cấp qua token file được giới hạn quyền theo [cloudflared run parameters](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/). Chốt image/version hỗ trợ cách cấp token đã chọn. SG không inbound nhưng phải có outbound để Tunnel và AWS hoạt động.

Kiểm tra theo thứ tự: API local health → connector healthy → hostname Tunnel gọi đúng API. Connector healthy chưa đủ chứng minh ứng dụng đằng sau chạy được. Chưa cần domain CloudFront ở bước M2.

### 7.2. Hoàn thiện script deploy trước khi dùng

[deploy-api.sh](../../scripts/deploy-api.sh) hiện chỉ truyền `SPRING_PROFILES_ACTIVE` và publish `8080:8080`; chưa đọc secret/config, chưa chạy Tunnel, chưa chờ kết quả SSM hoặc health check. Nguyên cần bổ sung các phần này, bind loopback và rollback khi phiên bản mới không khỏe.

[bump-worker-tag.sh](../../scripts/bump-worker-tag.sh) dùng đúng SSM path `/tvc/{env}/worker/image-tag` và ASG name `tvc-{env}-worker-asg`. Launch Template phải đọc path này khi boot; cần theo dõi refresh tới thành công/thất bại, và ghi lại tag trước khi đổi.

Sau khi đã hoàn thiện, cú pháp gọi từ root bằng Bash:

```bash
export ENV=dev
export TAG="$(git rev-parse HEAD)"
# Đặt ECR_REGISTRY theo URI registry thật của account trước bước này.
ENV="$ENV" TAG="$TAG" ECR_REPO="${ECR_REGISTRY:?cần ECR_REGISTRY}/tvc-backend" bash scripts/deploy-api.sh
ENV="$ENV" TAG="$TAG" bash scripts/bump-worker-tag.sh
```

Các script không build/push image. Tag trên phải đã tồn tại ở ECR và đúng phiên bản được kiểm thử. Trả về SSM command ID hoặc refresh ID chỉ là bắt đầu thao tác; kiểm tra trạng thái hoàn tất và chạy E2E sau deploy.

## 8. Edge, quan sát và CI/CD — C4/C5, C6 nếu còn thời gian

### 8.1. Hoàn thiện CloudFront — M3

1. Build frontend bằng lệnh App cung cấp, upload artifact vào bucket frontend private.
2. Tạo S3 REST origins cho frontend/output, OAC và bucket policy giới hạn đúng distribution.
3. Tạo origin HTTPS theo hostname Tunnel; behavior `/api/*` không cache, không chuyển Host của viewer, chuyển thông tin auth cần thiết.
4. Thêm behavior `/media/*` với rewrite bỏ `/media`; kiểm tra master playlist, rendition, segment và thumbnail, không chỉ status 200 của trang web.
5. Thử deep link React, đăng nhập, upload, polling và playback qua `*.cloudfront.net`; thêm domain riêng/ACM khi đã ổn.

Thiết lập chi tiết và nguồn AWS nằm ở [Designs, mục 7](3.%20Designs.md). Tránh fallback SPA áp dụng cả lỗi API/media. Chạy lại E2E với base URL CloudFront; chỉ đánh dấu M3 khi user flow và scaling đều đạt.

### 8.2. Quan sát và co giãn

Nguyên/Vũ đưa log JSON lên CloudWatch, tạo dashboard, alarm DLQ và SNS; kiểm tra subscription thực sự nhận thông báo. Đầu tiên thử 1 → 2 → 1 với workload đủ tạo backlog; ghi queue depth, số worker, thời điểm scale và kết quả job.

Chỉ bật min 0 sau khi metric publisher hoạt động ngoài ASG và thử một job từ trạng thái 0 máy thành công. Kiểm tra cả instance đang giữ job trong đợt scale-in/Instance Refresh. Không dùng kill worker local thay cho phép thử Spot/ASG trên AWS.

### 8.3. CI/CD — các phần còn phải hoàn thiện

CI hiện tự chạy PR/push `main`, chỉ build/test module có manifest và validate Terraform khi có `.tf`. Deploy là `workflow_dispatch`, input hiện chỉ có `env`; tag lấy từ `github.sha`.

- Cấu hình OIDC trust giới hạn đúng repository/ref hoặc GitHub Environment, quyền deploy theo môi trường.
- Workflow hiện **chưa gắn job với GitHub Environment**; input `env` không tự đổi các biến `FRONTEND_BUCKET`, distribution ID hay deploy role. Cần environment mapping cho `dev`/`demo` trước khi dùng chung workflow.
- Khai báo `AWS_DEPLOY_ROLE_ARN`, `ECR_REGISTRY`, `FRONTEND_BUCKET`, `CLOUDFRONT_DISTRIBUTION_ID` đúng scope.
- Bổ sung theo dõi SSM/Instance Refresh, health check, smoke/E2E sau deploy, thứ tự triển khai frontend tương thích backend và chặn hai deploy cùng env chạy chồng nhau.
- Không coi việc workflow trả xanh sau `send-command`/`start-instance-refresh` là xác nhận rollout thành công.
- Nếu muốn rollback bằng SHA tùy chọn qua giao diện workflow, cần bổ sung input và checkout/image selection; workflow hiện chưa hỗ trợ input đó.

Hoãn C6 không hoãn việc kiểm tra deploy/rollback thủ công của P0.

## 9. Benchmark, chaos và nghiệm thu — A8/M4

Lưu dùng cùng dataset hợp lệ, cùng image/FFmpeg profile và loại máy on-demand. Đo 1 worker rồi 2 worker cố định; thử autoscaling ở một lượt riêng. Ghi warm/cold start và workload để không trộn thời gian boot với throughput ổn định.

Mỗi lượt lưu: commit/image digest, region/instance type, số worker, dung lượng/thời lượng input, thời điểm submit/start/finish, retry, success/failure và chi phí theo khoảng đo. Tính throughput = video hoàn thành / thời gian đo; thời gian chờ = start − submit; thời gian xử lý = finish − start. Time-to-playable cần ghi rõ điểm bắt đầu đo và kết thúc khi HLS thực sự truy cập được.

Chaos tối thiểu: dừng một worker lúc `PROCESSING`, quan sát visibility hết hạn và worker khác nhận lại, xác minh output/state; sau đó kiểm tra ca lỗi lặp lại vào DLQ. Không sửa tay DynamoDB thành `COMPLETED` để vượt kiểm thử.

Lưu dữ liệu thô, biểu đồ, cấu hình và kết luận trong vùng báo cáo theo quy ước nhóm; ghi các giới hạn như dataset nhỏ, variance Spot, CPU credit hoặc cold start. M4 cần bằng chứng, không yêu cầu khẳng định tốc độ tăng đúng gấp đôi.

## 10. Rollback, demo và thu dọn

### Rollback

Trước deploy ghi image tag/digest cũ, cấu hình SSM liên quan và artifact frontend cũ. Khi phiên bản mới lỗi, triển khai lại tag cũ cho API; trả worker parameter về tag cũ rồi thực hiện refresh phù hợp với trạng thái đợt refresh đang chạy; chờ job đang xử lý an toàn. Khôi phục frontend artifact tương thích và invalidation đúng đường dẫn.

Revert code Terraform rồi **review plan trước apply**; đây không phải rollback dữ liệu tự động. Thay schema/bucket hoặc xóa tài nguyên cần kế hoạch phục hồi riêng. Sau rollback chạy lại health/E2E và ghi kết quả.

### Thu dọn

Local: `make down` dừng và xóa container; `make reset` xóa stack/volume rồi dựng LocalStack lại. Chỉ dùng reset với dữ liệu thử có thể bỏ; init hiện chưa bảo đảm idempotent nếu tự bổ sung persistence.

AWS: xuất bằng chứng/dữ liệu cần giữ, chọn đúng env và xem trước kế hoạch xóa. **Chỉ sau khi `envs/demo` đã được triển khai**, dùng:

```bash
terraform -chdir=infra/terraform/envs/demo plan -destroy
terraform -chdir=infra/terraform/envs/demo destroy
```

Không xóa bucket state dùng chung. Bucket còn object/version, ECR image, resource tạo tay hoặc Tunnel/DNS ngoài Terraform có thể cần thu dọn riêng theo inventory; không bật `force_destroy` hàng loạt chỉ để lệnh chạy qua. Kiểm tra EC2/ASG/EBS/public IP/log còn lại và chi phí sau buổi thử nghiệm; giảm min worker về 0 không tắt toàn bộ chi phí môi trường.

## 11. Xử lý sự cố nhanh

| Triệu chứng | Kiểm tra đầu tiên |
|---|---|
| Không có `make` | Dùng Compose/Bash tương đương, hoặc cài GNU Make vào shell đang dùng |
| Init không chạy / lỗi CRLF | Log LocalStack, LF và executable bit của init script; đối chiếu `.gitattributes` |
| LocalStack thiếu token / pull lỗi | `.env`, phiên bản image và credential dịch vụ; không đưa token vào log chia sẻ |
| `make up` báo thiếu Dockerfile | Source/image chưa được hoàn thiện; quay lại mục 4 |
| nginx `/` 502 | Vite host cổng 5173, bind address và `host.docker.internal` |
| nginx `/api` 502 | Backend có chạy không, cổng 8080 và prefix `/api` |
| Presigned URL lỗi | URL host dùng được trong browser, CORS, header lúc PUT và chữ ký; đừng thay host sau ký |
| Terraform không có cấu hình | Chưa có module/root `.tf`; README không phải mã Terraform |
| Cloud API 403/502 | API health tại EC2 → Tunnel origin → CloudFront; policy Host/auth và cache |
| HLS 403/404 hoặc trả HTML | OAC/bucket policy, rewrite `/media`, object key, Content-Type, SPA fallback |
| Worker không nhận job | Queue URL/region, IAM, cấu hình runtime, ECR image, log boot/SSM và DLQ |
| ASG 0 không lên | Publisher còn chạy không, metric có datapoint không, policy đánh thức và quota/capacity |
| Instance Refresh đứng chờ | Worker còn protection/job, lịch sử refresh; không tắt protection mù khi job đang chạy |
