# 5. API Integration — Week1 DRAFT

**Trạng thái: đề xuất frontend, CHƯA được backend/App/Cloud phê duyệt.** Người dùng đã cho phép bổ sung schema DRAFT để Week1 không bị chặn; việc này không thay thế review của Phương. Mọi nội dung mang nhãn **giả định — chờ Phương xác nhận** bên dưới là đầu vào review tuần 9, không phải cam kết backend đang triển khai.

Nguồn đối chiếu: `../contracts/openapi.yaml`, `dynamodb-tables.md`, `s3-key-convention.md`, `upload-limits.md`, `video-state-machine.md` và `work/Week1.md`. Không sửa các contract DynamoDB/S3/worker trong Week1 này. OpenAPI giữ nguyên toàn bộ endpoint cũ, bổ sung path parameter hợp lệ; `info.version` vẫn là `0.1.0`, có `x-contract-status: DRAFT — proposed, not approved`.

## 1. Interface và đường đi dữ liệu

- **giả định — chờ Phương xác nhận:** UI chỉ dùng `src/api/client.ts`; cùng một interface cho `VITE_API_MODE=mock|real`. Client luôn fetch đường dẫn tương đối `/api/...`; không ghép origin từ biến môi trường. Chỉ adapter fetch trong Node test resolve `http://localhost:5173`. `/media/...` cũng tương đối.
- **giả định — chờ Phương xác nhận:** `types.ts` alias trực tiếp `components['schemas'][...]` trong `schema.d.ts`, không viết DTO thứ hai. Sinh lại bằng `npm run api:generate --prefix frontend`; kiểm tra drift bằng `npm run api:check --prefix frontend`. Generated type chỉ bảo vệ compile time; boundary guards kiểm tra response/storage, AJV kiểm tra schema đầy đủ trong test.
- **giả định — chờ Phương xác nhận:** các response thành công là object trực tiếp, không bọc `data`; riêng list là `{items, nextCursor?}`. JSON dùng camelCase; timestamp là ISO date-time. Trường optional **bỏ hẳn**, không gửi `null`. Object schema dùng `additionalProperties: false` trừ map upload headers; runtime client kiểm tra các trường cần dùng nhưng không thay thế full JSON Schema validation.

**giả định — chờ Phương xác nhận:** mock list dùng trang tối đa 50 record, thứ tự seed rồi record mới theo thứ tự tạo; cursor nội bộ base64url của ID cuối nhưng consumer phải coi opaque, chỉ URL-encode. Chưa có cancel/snapshot consistency khi list thay đổi giữa trang.

## 3. Endpoint và status mapping

Tất cả đường dẫn dưới có prefix `/api`; các lỗi JSON dùng `ErrorResponse`. `default` trong OpenAPI dành lỗi bất ngờ (bao gồm 5xx), không có nghĩa mock dựng đầy đủ backend.

| Endpoint | Thành công | Lỗi đề xuất / hành vi | Trạng thái |
|---|---|---|---|
| `POST /auth/login` | 200 `Session` | 400 JSON hỏng/non-object; 422 thiếu/lạ/sai field; 401 `INVALID_CREDENTIALS`; 5xx. Không bearer, không đọc token cũ, không xóa phiên đang có khi login sai. | **giả định — chờ Phương xác nhận** |
| `GET /projects` | 200 `ProjectList` | 401, 403, 422 `INVALID_CURSOR`, 5xx. | **giả định — chờ Phương xác nhận** |
| `POST /projects` | 201 `Project` | 400, 401, 403, 422 validation, 5xx. Không idempotency key. | **giả định — chờ Phương xác nhận** |
| `GET /projects/{projectId}/videos` | 200 `VideoList` | 401, 403, 404 `NOT_FOUND`, 422 cursor, 5xx. | **giả định — chờ Phương xác nhận** |
| `POST /projects/{projectId}/videos` | 201 `UploadTicket` | 400, 401, 403, 404, 413 `UPLOAD_TOO_LARGE`, 422 `VALIDATION_ERROR`/`UNSUPPORTED_FORMAT`, 5xx. | **giả định — chờ Phương xác nhận** |
| `GET /videos/{videoId}` | 200 `Video` | 401, 403, 404, 5xx. | **giả định — chờ Phương xác nhận** |
| `POST /videos/{videoId}/confirm` | 202 `Video` | Không request body; body không rỗng → 400 `INVALID_REQUEST`. 401/403/404; 409 `UPLOAD_NOT_COMPLETE` hoặc `VIDEO_NOT_CONFIRMABLE`; 413/422 dành backend kiểm tra object (mock đã chặn ở PUT); 5xx. | **giả định — chờ Phương xác nhận** |
| `POST /auth/register` | Giữ 201 skeleton | Ngoài Week1; security public đề xuất, request/response chưa chốt, không MSW handler/UI. | **giả định — chờ Phương xác nhận** |
| `POST /projects/{projectId}/api-keys` | Giữ 201 skeleton | Ngoài Week1; path parameter hợp lệ, kế thừa bearer đề xuất; scope/key auth/request/response chưa chốt, không handler/UI. | **giả định — chờ Phương xác nhận** |

- **giả định — chờ Phương xác nhận:** protected requests bắt buộc `Authorization: Bearer <accessToken>` từ `readSession`, không từ caller. Thiếu token, token không được mock cấp, token hết hạn → 401 `UNAUTHORIZED`. User khác demo trong registry → 403 `FORBIDDEN`; mock không có đăng ký/user thứ hai nên chưa diễn tập ownership/multi-tenant thật. Resource không tồn tại với session hợp lệ → 404. Auth kiểm tra trước body/resource.
- **giả định — chờ Phương xác nhận:** malformed JSON → 400 `INVALID_JSON`; JSON không phải object → 400 `INVALID_REQUEST`; thiếu field, field lạ, sai kiểu/giới hạn → 422 `VALIDATION_ERROR`. Extension/MIME sai → 422 `UNSUPPORTED_FORMAT`. Số byte nguyên vượt max → 413, còn size âm/zero/phân số → 422. Chưa enforce request Content-Type JSON trong mock; backend phải xác nhận chính sách 415.
- **giả định — chờ Phương xác nhận:** client throw `ApiError extends Error {status, code}`. Offline/fetch rejection → `status=0, code=NETWORK_ERROR`; không-JSON hoặc sai shape trong 2xx → `INVALID_RESPONSE` giữ status. Lỗi HTTP đọc được envelope thì giữ code/message; nếu không, 401 → `UNAUTHORIZED`, ≥500 → `SERVER_ERROR`, lỗi khác → `HTTP_ERROR`. Không hiển thị raw HTML proxy làm message. Không retry tự động, không timeout/cancel API client trong Week1 (riêng PUT xem mục 5.7).
- **giả định — chờ Phương xác nhận:** protected 401 luôn `clearSession()` rồi `window.dispatchEvent(new Event('tvc:session-expired'))`, kể cả body HTML/hỏng. Không phát expiry cho login thất bại hay offline/403/5xx. UI sở hữu timer hết hạn và route redirect; API module không có timer/polling.

## 5. Giới hạn, PUT, retry và idempotency

| Quy tắc | Hành vi Week1 | Trạng thái |
|---|---|---|
| Byte limit | `209715200` (200 MiB, tài liệu gọi 200 MB); API khai báo và mock PUT đều kiểm tra, giá trị bằng max được nhận. Không dùng 200000000. | **giả định — chờ Phương xác nhận** |
| Extension/MIME | Case-insensitive extension, MIME exact lowercase: `.mp4` ↔ `video/mp4`, `.mov` ↔ `video/quicktime`, `.mkv` ↔ `video/x-matroska`, `.webm` ↔ `video/webm`. MIME rỗng, octet-stream, alias hoặc pair lệch bị từ chối. UI transport có thể chọn MIME từ extension trước khai báo. | **giả định — chờ Phương xác nhận** |
| Worker validation | 300 giây, cao 1080 pixel và codec/container thực tế do ffprobe quyết định; mock chỉ biết khai báo/byte length/MIME, không xác nhận file là video thật. Không enforce duration/resolution trên frontend API. | **giả định — chờ Phương xác nhận** |
| Storage lifecycle | 7 ngày giữ nguồn là chính sách S3 DRAFT, không thực thi bằng localStorage. Không multipart; mock cũng không lưu binary lâu dài. | **giả định — chờ Phương xác nhận** |
| Headers | Browser tự quản Content-Length, không set thủ công header bị cấm. Mock yêu cầu Content-Type đúng ticket. Backend phải kiểm nghiệm signed length/HeadObject và CORS, không suy rằng presigned PUT tự enforce size. Không gửi API bearer/cookie credentials qua upload transport. | **giả định — chờ Phương xác nhận** |

Luồng cụ thể:

1. **giả định — chờ Phương xác nhận:** `createVideo` tạo metadata `UPLOADING`, tăng project count, trả ticket 15 phút. Không `Idempotency-Key`, không endpoint refresh/cancel/delete upload. POST lặp tạo video khác; **không tự retry create project/video/login** khi không biết server đã ghi hay chưa. Ticket bị mất/hết hạn chưa có resume/reissue contract; upload mới có thể để lại metadata UPLOADING cũ.
2. **giả định — chờ Phương xác nhận:** PUT mô phỏng ở **`/__mock-upload/:videoId?token=<random capability>`**, không `/api`, không backend endpoint và không thêm vào OpenAPI SaaS inventory. Không cần bearer; capability đủ quyền trong 15 phút. Resource thiếu → 404 `NOT_FOUND`; token thiếu/sai → 403 `INVALID_UPLOAD_TOKEN`; hết hạn → 403 `UPLOAD_URL_EXPIRED`; video đã confirm → 409 `VIDEO_NOT_CONFIRMABLE`.
3. **giả định — chờ Phương xác nhận:** mock đọc toàn bộ `request.arrayBuffer()` và so `byteLength` với khai báo; >max → 413 `UPLOAD_TOO_LARGE`; khác size → 422 `UPLOAD_SIZE_MISMATCH`; Content-Type khác → 422 `UPLOAD_TYPE_MISMATCH`. Không tin riêng Content-Length. PUT hợp lệ chờ khoảng **1200 ms**, kiểm tra signal/expiry lần nữa rồi đánh dấu `uploaded=true`, trả 200 body rỗng. Bị abort trước đánh dấu không confirm được. Đây là mô phỏng in-memory, không streaming/checksum/HeadObject/S3.
4. **giả định — chờ Phương xác nhận:** `VITE_MOCK_UPLOAD_FAILURE_ONCE=true` làm **PUT hợp lệ đầu tiên** trong một instance trả `HttpResponse.error()` sau delay; request sai không tiêu thụ lỗi một lần. Retry cùng URL/file/headers khi còn hạn sẽ thành công. Flag một-lần nằm memory; reload/new handler factory sẽ bật lại theo env, không persist flag. PUT bị lỗi không đánh dấu hoàn tất; đã PUT thành công có thể PUT lặp cùng ticket trước confirm mà không tạo video thứ hai.
5. **giả định — chờ Phương xác nhận:** gọi confirm chỉ sau PUT thành công. Không có uploaded marker → 409 `UPLOAD_NOT_COMPLETE`. Thành công `UPLOADING → PENDING`, cập nhật `updatedAt`, trả **202**, không 200/204. PENDING confirm lặp trả nguyên object, không đổi timestamp; sau PROCESSING/COMPLETED/FAILED_* trả 409, không regression. Khi confirm mất response, retry confirm an toàn theo đề xuất này; real API còn phải đảm bảo enqueue idempotent, mock không chứng minh được SQS exactly-once.
6. **giả định — chờ Phương xác nhận:** marker thành công persist, nên có thể reload rồi confirm kể cả URL PUT đã hết hạn; URL expiry chỉ giới hạn PUT, không xóa object đã upload. Không tự chuyển PENDING sang PROCESSING/COMPLETED trong Week1, không worker/polling. Transport/UI thuộc phần khác: dùng XHR và progress mô phỏng theo thời gian khi mock; delay MSW không phải bằng chứng byte-progress/S3 thật. Không quảng cáo mock tiến trình là network throughput thực.
7. **giả định — chờ Phương xác nhận:** XHR transport **không** đặt giới hạn tổng thời gian cho PUT, vì 209715200 byte trên đường truyền chậm hợp lệ có thể vượt mọi cap; thay vào đó chỉ hủy khi không nhận `upload.progress` nào trong 120 giây và báo lỗi retry được. Backend/S3 không có hành vi tương ứng để xác nhận; đây là lựa chọn frontend.
8. **giả định — chờ Phương xác nhận:** modal cho phép đóng trong lúc chờ confirm. Theo mục 5, confirm lặp trên PENDING trả nguyên snapshot nên không tạo video thứ hai; lần bấm đóng chỉ ngừng chờ, danh sách reload là nguồn sự thật. Nếu real enqueue không idempotent thì hành vi này lộ trùng job — phải chốt ở tuần 9.

## 8. Week 2 — mock processing, media, polling, player và embed (2026-10-30)

Toàn bộ mục này là **giả định — chờ Phương xác nhận**; interface UI và relative paths `/api/*`, `/media/*` giữ nguyên như Week 1.

1. **Mock state machine:** confirm chuyển `UPLOADING → PENDING`; mỗi lần đọc list/detail (mock) tự chuyển `PENDING → PROCESSING` sau ≥5 giây và `PROCESSING → COMPLETED` sau ≥10 giây kể từ `updatedAt`. `VITE_MOCK_PROCESS=fail` thay bước cuối bằng `FAILED_TRANSCODE` + `errorCode=TRANSCODE_FAILED`; `freeze` không chuyển trạng thái. Fixture seed có `updatedAt` cũ nên ở chế độ auto, `PENDING`/`PROCESSING` seed tự hoàn tất ngay lần đọc đầu — dùng `freeze` khi cần xem trạng thái trung gian.
2. **Polling:** hook dùng chung poll mỗi **3000 ms** khi dữ liệu còn `PENDING`/`PROCESSING`, dừng ở trạng thái cuối, tạm dừng khi tab ẩn và chạy lại ngay khi hiện; không xếp chồng request (lịch chỉ đặt sau khi request trước kết thúc). Ba lỗi liên tiếp giữ dữ liệu cũ và hiện "Status unknown. Reload to try again."; lỗi lần đọc đầu hiện notice. Trong dev, React StrictMode gọi effect hai lần nên lần tải đầu có thể phát hai request trùng; production không có hành vi này. Interval 5 giây/`updatedAt` do worker thật quyết định — cần A4 xác nhận.
3. **Media fixture:** `hls.js` **1.7.4** (dependency mới). Mock phục vụ master + hai rendition 360p/720p tại `/media/{projectId}/{videoId}/hls/...`; mỗi rendition 5 segment 2 giây (tổng 10 giây), thumbnail JPEG tại `.../thumb/default.jpg`. Fixture sinh bằng FFmpeg `testsrc`, tổng **431.184 byte** (cao hơn mục tiêu ~100 KB; vẫn là H.264 hợp lệ, đủ để hls.js chọn rendition). Đây không phải output worker thật: không fMP4/`PROGRAM-DATE-TIME`, bitrate không đại diện.
4. **Player:** chỉ dùng master `assets.hls`; hls.js `MANIFEST_PARSED` → autoplay ở trang chi tiết (bị policy chặn thì vẫn còn native controls); Safari dùng native HLS qua `canPlayType('application/vnd.apple.mpegurl')`.    Kích thước/attributes iframe là giả định frontend. Clipboard dùng `navigator.clipboard.writeText`, fallback textarea readonly + `document.execCommand('copy')`; cần secure context (localhost/HTTPS), LAN IP HTTP có thể bị chặn.
